# 反馈遗留事项整理

> 更新：项目引入数据库后，反馈已改为**主后端 MySQL 落库** + **独立后台管理系统只读查看**，下面的 serverless/Worker 设想（#1、#2）已被取代并完成。本文保留作演进记录，最新现状见 [数据库和数据表说明](../数据库和数据表说明.md) 与 [AI 助手与登录系统说明](../技术架构和代码功能说明/AI助手与登录系统说明.md)。

## 已完成

- 独立反馈页 UI 已完成
- 反馈提交参数结构已明确
- 主后端提交失败时可在浏览器本地暂存
- 打赏页已独立出来
- 反馈已落库主后端 MySQL（`feedback` 表，匿名可提交、登录记账号）
- 独立后台只读查看页已上线（反馈、账号活动日志、分页工具使用日志）

## 当前遗留项

### 1. 反馈写入链路

状态：`已完成（改为主后端 MySQL 落库，不再依赖 Worker/表格）`

当前前端提交模块固定调用 `POST /api/feedback`。`VITE_FEEDBACK_ENDPOINT` 只残留在 `FeedbackPage.vue` 的 `deliveryHint` 展示文字中，不参与请求地址选择，因此不能通过配置该变量切换到 Worker、Google Sheets、Airtable 或飞书多维表格。

### 2. 反馈查看后台未单独建设

状态：`已完成（独立后台管理系统只读查看页）`

当前查看入口已迁移到自建独立后台，不再依赖第三方表格本身。

后台已经区分 `admin` 和 `viewer`。其中“后台配置管理”仍是路线图占位页，没有实际配置读写能力。

### 3. 通知能力未落地

状态：`待处理`  
优先级：`中`

可选目标：

- QQ 邮箱
- 钉钉机器人
- 飞书机器人

反馈落库已经稳定接入，后续可按运营需要补通知，并确保通知失败不影响用户提交结果。

### 4. 风控与反刷仍是建议态

状态：`待处理`  
优先级：`中`

当前尚未正式接入：

- Turnstile
- 更细的限流
- 反刷策略

### 5. 反馈字段标准

状态：`已完成（在主后端 schema、服务层和数据库表中固化）`

当前字段由 `backend/app/schemas/feedback.py`、`backend/app/services/feedback_service.py` 和 `feedback` 表共同约束。若将来新增 Worker 同步，应以主后端字段定义为准。

## 建议推进顺序

1. 补充通知能力，并保证通知失败不影响反馈落库
2. 增加限流、Turnstile 或其它反刷措施
3. 数据量增长后，把后台反馈列表从固定最近 500 条改为分页查询

## 建议的落地成果

后续继续完善时，建议至少产出：

1. 一种可监控、失败可重试的通知方式
2. 一套轻量限流和反刷配置
3. 后台反馈分页和筛选能力
4. 本地暂存草稿的可见重试入口
