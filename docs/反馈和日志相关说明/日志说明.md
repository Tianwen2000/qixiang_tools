# 日志说明

## 日志位置

当前后端应用会把运行日志写入项目根目录的 `log/` 文件夹：

- `log/backend-debug.log`：DEBUG 调试日志，适合排查细节问题。
- `log/backend-info.log`：INFO 普通信息日志，适合查看正常运行事件。
- `log/backend-warn.log`：WARN 警告日志，适合查看可恢复但需要关注的问题。
- `log/backend-error.log`：ERROR 错误日志，适合排查接口异常和系统错误。

日志文件使用滚动归档，每个文件达到一定大小后会自动轮转，避免单个文件无限增长。

## 开发环境

本地开发时，日志一般直接看两类：

1. 后端终端输出：适合立即查看接口启动、请求错误和调试信息。
2. 项目根目录 `log/`：适合回看历史问题，尤其是偶发异常。

`log/` 已加入 `.gitignore`，不会被提交到 GitHub。

## 线上服务器

线上服务器虽然也会生成项目内 `log/`，但不要只依赖它作为唯一日志来源。原因是：

- `rsync --delete` 同步代码时，如果没有排除运行日志，可能误删线上日志。
- Docker 部署时容器文件系统可能随容器重建而丢失，日志应挂载到宿主机或集中采集。
- systemd、Nginx、Docker 本身都有独立日志，排查线上问题时通常需要一起看。

建议线上同时保留这些日志入口：

- 后端服务：`journalctl -u qixiang-backend -f`
- Nginx 访问日志：`/var/log/nginx/access.log`
- Nginx 错误日志：`/var/log/nginx/error.log`
- Docker 容器日志：`docker logs --tail 100 容器名`
- 项目应用日志：`/home/ubuntu/qixiang_tools/log/`

## 同步注意

同步项目到服务器时，建议继续排除运行日志：

```bash
--exclude log/
--exclude logs/
--exclude '*.log'
```

这样可以避免本地日志覆盖服务器日志，也能避免服务器日志被同步删除。

## 隐私说明

工具使用日志只记录行为统计信息，例如工具名称、操作类型、成功失败、耗时、输入输出长度、错误码和截断后的错误信息，不保存用户完整输入和完整输出。
