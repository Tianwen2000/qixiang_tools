# 部署与更新指南

> 记录生产服务器的部署架构，以及改完代码后如何更新上线。配合 [项目常用命令汇总](./项目常用命令汇总.md) 使用。
> 出于安全，本文里服务器 IP、密码一律用占位符 `<服务器IP>` 表示，不写真实值。

## 1. 部署架构

| 项 | 说明 |
|---|---|
| 服务器 | Ubuntu，项目目录 `/home/ubuntu/qixiang_tools` |
| 前端 | nginx 静态托管 `frontend/dist`（站点 `/etc/nginx/sites-enabled/qixiang_tools`，`root .../frontend/dist`） |
| 接口反代 | nginx 把 `/api` 反代到 `http://127.0.0.1:8000/api/` |
| 后端 | systemd 服务 `qixiang-backend`（uvicorn，端口 8000），虚拟环境 `backend/.server-venv` |
| 当前同步方式 | **手动打包上传（方式一）——服务器上没有 `.git`，`git pull` 用不了** |

> `frontend/dist` 已纳入 git，本地改前端必须先 `npm run build` 再提交/上传。

下面给两种更新方式：**方式一**是现在服务器实际用的；**方式二**（git）更省事、且没有权限坑，推荐以后切过去。

---

## 2. 方式一：手动打包上传（服务器当前用的方式）

服务器是从本地用 scp / 工具上传的，没有 git 仓库，所以只能传文件。

### 2.1 本地打包
```bash
cd /Users/a123/PycharmProjects/qixiang_tools/frontend && npm run build   # 改了前端就重新打包

cd /Users/a123/PycharmProjects/qixiang_tools
# 按本次改动按需增减要打包的文件
tar czf /tmp/qx_update.tgz --exclude='._*' --exclude='__pycache__' \
  frontend/dist \
  backend/app/tools/<改动的模块>.py \
  backend/app/utils/validators.py \
  backend/app/configs/tools.json
```

### 2.2 上传 + 解压 + 重启
```bash
scp /tmp/qx_update.tgz ubuntu@<服务器IP>:/tmp/
ssh ubuntu@<服务器IP>
# —— 以下在服务器上执行 ——
cd /home/ubuntu/qixiang_tools && tar xzf /tmp/qx_update.tgz
sudo systemctl restart qixiang-backend     # 改了后端才需要
```

### 2.3 ⚠️ 关键：修正文件权限（否则 nginx 403）
**从 Mac 上传的文件常带 `600` 权限，nginx 读不了会报 403（背景 mp4 最容易中招）。** 解压后务必把目录设 755、文件设 644：
```bash
find /home/ubuntu/qixiang_tools/frontend/dist -type d -exec chmod 755 {} +
find /home/ubuntu/qixiang_tools/frontend/dist -type f -exec chmod 644 {} +
```

## 3. 方式二：git 部署（推荐，将来切过去）

把服务器项目改成 git 仓库后，更新会简单很多、也不会有权限坑：

```bash
# 一次性切换（在服务器上，注意先备份 backend/.server-venv 等本地产物）
cd /home/ubuntu
git clone git@github.com:Tianwen2000/qixiang_tools.git qixiang_tools_git
# 迁移服务器专属的 .server-venv、frontend/.env 等，再把 nginx root / systemd 指到新目录

# 以后每次更新：
cd /home/ubuntu/qixiang_tools && git pull
sudo systemctl restart qixiang-backend     # 改了后端才需要
```

git 方式：前端 `git pull` 后 nginx 直接生效（浏览器硬刷新），保留正确权限、无需手动打包，**强烈建议尽快切到这种方式**。

---

## 4. 按改动类型要做什么

| 改了… | 操作 |
|---|---|
| 只改前端 | 重新 `npm run build` → 传 `dist`（或 `git pull`）→ 浏览器硬刷新 |
| 改了后端 `.py` | 传/pull 后 `sudo systemctl restart qixiang-backend` |
| 改了 `requirements.txt` | 先 `./backend/.server-venv/bin/pip install -r backend/requirements.txt` 再 restart |
| 改了 nginx 配置 | `sudo nginx -t` → `sudo systemctl reload nginx` |

## 5. 验证
```bash
systemctl is-active qixiang-backend                                          # active
curl -s 127.0.0.1:8000/api/health                                            # {"code":0,...}
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1/wallpaper/spring.mp4   # 200（不是 403）
```

## 6. 常见问题
- **背景 mp4 / 图片 403**：文件权限是 `600`，nginx 读不了 → 按 2.3 用 `chmod 644` 修。
- **前端没更新**：忘了 `npm run build` 或没传 `dist`；或浏览器缓存 → 硬刷新。
- **后端 500 / 起不来**：`sudo journalctl -u qixiang-backend -n 80 --no-pager` 看日志（常见是依赖没装或代码报错）。
- **`/api` 502**：后端没起来 → 先 `systemctl is-active qixiang-backend`。

## 7. 关键路径速查
- 项目目录：`/home/ubuntu/qixiang_tools`
- 前端产物（nginx root）：`frontend/dist`
- 后端入口：`backend/app/main.py`（systemd `qixiang-backend`）
- 后端虚拟环境：`backend/.server-venv`
- nginx 站点配置：`/etc/nginx/sites-enabled/qixiang_tools`
- 后端日志：`sudo journalctl -u qixiang-backend`
