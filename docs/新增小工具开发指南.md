# 新增小工具开发指南

这份文档按“初学者能照着做”的方式写，只讲当前项目真实可用的做法。

新增工具时先记住一句话：

> 工具是否出现在页面上，主要由后端 `backend/app/configs/tools.json` 决定；工具具体怎么执行，取决于后端 `backend/app/tools/` 或前端专用组件。

## 1. 先判断工具类型

新增前先判断它属于哪一种。

| 类型 | 适合场景 | 通常改哪些文件 |
| --- | --- | --- |
| 文本工具 | 输入文本，输出文本或文件 | 后端工具模块 + `tools.json` |
| 文件工具 | 上传文件，输出文本或文件 | 后端工具模块 + `tools.json` + 上传校验 |
| 纯前端工具 | 数据只在浏览器本地处理，不上传后端 | Vue 组件 + `ToolPage.vue` + `tools.json` |
| 定制工具 | 交互复杂，普通表单放不下 | Vue 组件 + 必要后端接口或配置 |

### 最推荐的选择

- 能用普通文本表单就用 `ToolTextForm`。
- 能用普通文件上传就用 `ToolFileForm`。
- 只有复杂交互才写新的 `ToolXxx.vue`。

## 2. 命名规则

### 工具 slug

工具 slug 用小写中划线：

```text
my-text-tool
headers-to-json
json-body-formatter
```

slug 会出现在 URL、收藏、后台日志和工具配置里，确定后不要随便改。

### Python 模块名

后端工具文件用小写下划线：

```text
backend/app/tools/my_text_tool.py
```

`tools.json` 里的 `module` 必须和文件名一致：

```json
{
  "module": "my_text_tool"
}
```

### Vue 组件名

前端专用组件用 `ToolXxx.vue`：

```text
frontend/src/components/ToolMyLocalTool.vue
```

## 3. 新增普通文本工具

文本工具适合“输入一段文字，点击执行，输出一段结果”。

### 第一步：新增后端工具文件

路径：

```text
backend/app/tools/my_text_tool.py
```

示例代码：

```python
"""文件说明：演示一个普通文本工具，把输入文本加上前缀后返回。"""

from app.core.exceptions import AppException


def run(text: str, prefix: str = "", **_: dict) -> str:
    """工具执行入口；ToolTextForm 会把输入文本和 params 传进来。"""
    if not text.strip():
        raise AppException(message="请输入内容", code=4001, status_code=400)
    return f"{prefix}{text}"
```

说明：

- `run()` 是后端工具入口，名字必须叫 `run`。
- `text` 是用户输入框里的内容。
- `prefix` 是参数名，来自 `tools.json` 的 `params`。
- `**_` 用来接住暂时不用的额外参数，避免未来扩展时报错。
- 出错时优先抛 `AppException`，这样前端 toast 会显示中文错误。

### 第二步：注册到 tools.json

路径：

```text
backend/app/configs/tools.json
```

新增一项：

```json
{
  "slug": "my-text-tool",
  "module": "my_text_tool",
  "name": "我的文本工具",
  "category": "text",
  "summary": "给文本加前缀。",
  "description": "输入一段文本，执行后会在前面加上指定前缀。",
  "input_mode": "text",
  "result_type": "text",
  "component": "ToolTextForm",
  "enabled": true,
  "params": [
    {
      "key": "prefix",
      "label": "前缀",
      "type": "text",
      "default": "",
      "placeholder": "请输入前缀"
    }
  ]
}
```

关键字段说明：

| 字段 | 作用 |
| --- | --- |
| `slug` | 工具唯一 ID，不能和已有工具重复 |
| `module` | 后端 Python 文件名，不带 `.py` |
| `name` | 页面上显示的工具名称 |
| `category` | 所属分类，例如 `text`、`ops`、`format` |
| `summary` | 工具卡片短说明 |
| `description` | 工具详情页说明 |
| `input_mode` | `text` 表示文本工具 |
| `result_type` | `text` 表示结果区展示文本 |
| `component` | 普通文本工具使用 `ToolTextForm` |
| `params` | 参数控件列表 |

### 第三步：重启后端

新增工具模块后必须重启后端，否则后端还不知道有新文件。

本地常用方式：

```bash
cd /Users/a123/PycharmProjects/qixiang_tools/backend
./.venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

如果后端已经在跑，先停掉再启动。

### 第四步：验证

打开前端页面，找到工具并测试。

也可以直接调后端接口：

```bash
curl -sS -H 'Content-Type: application/json' \
  -d '{"text":"hello","params":{"prefix":"前缀："}}' \
  http://127.0.0.1:8000/api/tools/my-text-tool/execute
```

## 4. 新增普通文件工具

文件工具适合“上传一个文件，后端处理后返回结果”。

### 第一步：新增后端工具文件

路径：

```text
backend/app/tools/my_file_tool.py
```

示例代码：

```python
"""文件说明：演示一个文件工具，读取上传文件并输出文件大小。"""

from pathlib import Path

from app.core.exceptions import AppException


def run(input_path: str, output_dir: str, filename: str = "", content_type: str = "", **params) -> str:
    """文件工具执行入口；input_path 是上传后的临时文件路径。"""
    path = Path(input_path)
    if not path.exists():
        raise AppException(message="上传文件不存在，请重新上传", code=4001, status_code=400)
    return f"文件名：{filename}\n文件大小：{path.stat().st_size} 字节\nMIME：{content_type}"
```

参数说明：

| 参数 | 说明 |
| --- | --- |
| `input_path` | 后端保存的临时上传文件路径 |
| `output_dir` | 本次请求的输出目录 |
| `filename` | 用户上传的原始文件名 |
| `content_type` | 浏览器上传时带来的 MIME 类型 |
| `**params` | `tools.json` 里配置的参数 |

如果要返回下载文件，就把生成文件写到 `output_dir`，然后返回文件路径。

### 第二步：注册到 tools.json

```json
{
  "slug": "my-file-tool",
  "module": "my_file_tool",
  "name": "我的文件工具",
  "category": "ops",
  "summary": "读取上传文件信息。",
  "description": "上传文件后显示文件名、大小和 MIME 类型。",
  "input_mode": "file",
  "result_type": "text",
  "component": "ToolFileForm",
  "enabled": true,
  "params": []
}
```

### 第三步：补上传校验

文件上传会先过校验。

如果你的工具需要新的文件类型，要检查：

```text
backend/app/utils/validators.py
```

例如只允许图片、PDF、ZIP、音视频等，项目里一般已有对应白名单和大小限制。

不要为了省事放开所有类型。文件工具一定要考虑服务器压力和安全风险。

## 5. 新增纯前端工具

纯前端工具适合“不上传后端，数据只在浏览器本地处理”。

今天新增的两个工具就是这种模式：

- `frontend/src/components/ToolKvHeadersToJson.vue`
- `frontend/src/components/ToolJsonBodyFormatter.vue`

### 第一步：新增组件

路径：

```text
frontend/src/components/ToolMyLocalTool.vue
```

示例代码：

```vue
<script setup>
// 文件说明：演示一个纯前端工具，把输入文本反转后输出。
import { ref } from "vue";

import ResultPanel from "./ResultPanel.vue";

const props = defineProps({
  tool: {
    type: Object,
    required: true,
  },
});

const input = ref("");
const output = ref("");
const error = ref("");

function convert() {
  error.value = "";
  if (!input.value) {
    error.value = "请输入内容";
    return;
  }
  output.value = [...input.value].reverse().join("");
}

function clearAll() {
  input.value = "";
  output.value = "";
  error.value = "";
}
</script>

<template>
  <section class="local-text-tool">
    <textarea v-model="input" rows="10" placeholder="请输入内容"></textarea>
    <div class="tool-actions">
      <button type="button" @click="convert">转换</button>
      <button type="button" class="secondary-button" @click="clearAll">清空输入</button>
    </div>
    <p v-if="error" class="local-message error">{{ error }}</p>
    <ResultPanel v-if="output" :result="output" result-type="text" />
  </section>
</template>
```

### 第二步：在 ToolPage.vue 注册组件

路径：

```text
frontend/src/pages/ToolPage.vue
```

做两件事：

1. `import ToolMyLocalTool from "../components/ToolMyLocalTool.vue";`
2. 在 `componentMap` 里加入：

```js
ToolMyLocalTool,
```

### 第三步：在 ui-mapping.js 里映射

路径：

```text
frontend/src/data/ui-mapping.js
```

如果这个文件里有工具 slug 到组件名的映射，要补上：

```js
"my-local-tool": "ToolMyLocalTool",
```

### 第四步：注册到 tools.json

```json
{
  "slug": "my-local-tool",
  "module": "frontend_only",
  "name": "我的本地工具",
  "category": "ops",
  "summary": "浏览器本地处理文本。",
  "description": "所有输入只在浏览器里处理，不会上传后端。",
  "input_mode": "local",
  "result_type": "text",
  "component": "ToolMyLocalTool",
  "enabled": true,
  "params": []
}
```

说明：

- 纯前端工具也需要写进 `tools.json`，否则首页和分类页不会显示。
- `module` 可以写占位值，实际执行不走后端工具模块。
- 纯前端工具不要调用后端转换接口。
- 如果要记录工具使用行为，只上报行为摘要，不上传用户完整输入输出。

## 6. 参数控件怎么写

普通文本/文件工具的参数由 `params` 控制。

当前通用表单支持：

- `text`
- `textarea`
- `select`
- `radio`

### text

```json
{
  "key": "keyword",
  "label": "关键词",
  "type": "text",
  "default": "",
  "placeholder": "请输入关键词"
}
```

### textarea

```json
{
  "key": "template",
  "label": "模板",
  "type": "textarea",
  "default": "",
  "placeholder": "请输入模板"
}
```

### select

下拉框统一使用自定义组件 `GlassSelect`，不要使用浏览器原生 `<select>`。

```json
{
  "key": "mode",
  "label": "模式",
  "type": "select",
  "default": "fast",
  "options": [
    { "label": "快速", "value": "fast" },
    { "label": "精准", "value": "accurate" }
  ]
}
```

### radio

```json
{
  "key": "direction",
  "label": "转换方向",
  "type": "radio",
  "default": "a_to_b",
  "options": [
    { "label": "A 转 B", "value": "a_to_b" },
    { "label": "B 转 A", "value": "b_to_a" }
  ]
}
```

### 条件显示 showWhen

某些参数只在特定模式下显示：

```json
{
  "key": "quality",
  "label": "质量",
  "type": "select",
  "default": "80",
  "showWhen": {
    "mode": "compress"
  },
  "options": [
    { "label": "80", "value": "80" },
    { "label": "90", "value": "90" }
  ]
}
```

## 7. 结果怎么返回

### 返回普通文本

后端 `run()` 直接返回字符串：

```python
return "处理完成"
```

`result_type` 写：

```json
"result_type": "text"
```

### 返回文件

后端生成文件并返回文件路径：

```python
from pathlib import Path


def run(input_path: str, output_dir: str, **params) -> str:
    output_path = Path(output_dir) / "result.txt"
    output_path.write_text("文件内容", encoding="utf-8")
    return str(output_path)
```

`result_type` 写：

```json
"result_type": "file"
```

前端 `ResultPanel` 会展示下载按钮。

## 8. 失败提示怎么写

后端工具不要直接 `raise Exception("xxx")`。

推荐：

```python
from app.core.exceptions import AppException

raise AppException(message="请输入内容", code=4001, status_code=400)
```

这样前端会收到统一格式：

```json
{
  "code": 4001,
  "message": "请输入内容",
  "data": null
}
```

用户看到的是中文 toast，不会暴露底层报错。

## 9. 工具展示顺序怎么调

普通情况下，工具顺序来自：

```text
backend/app/services/tool_loader.py
```

里面的 `CATEGORY_TOOL_ORDER` 可以给某个分类里的工具指定顺序。

示例：

```python
CATEGORY_TOOL_ORDER = {
    "format": {
        "png-jpg-ico-converter": 1,
        "animated-frames-converter": 2,
    }
}
```

说明：

- 写了排序的工具按数字从小到大排。
- 没写排序的工具仍然会正常显示，只是排在配置排序之后。
- 后续你自己新增工具后，可以把 slug 加进对应分类的排序表。

## 10. 工具使用日志怎么处理

当前前端会静默上报工具使用行为。

上报文件：

```text
frontend/src/api/tool-usage.js
```

后端接口：

```text
POST /api/tool-usage-logs
GET /api/backoffice/tool-usage-logs
```

原则：

- 记录谁在什么时候用了哪个工具。
- 记录操作类型、成功失败、耗时、输入长度、输出长度。
- 不记录用户完整输入。
- 不记录用户完整输出。
- 日志写入失败不能影响工具本身使用。

如果新增普通工具，通用表单已经会自动上报。

如果新增纯前端定制组件，需要自己在合适位置调用：

```js
import { buildToolUsageBase, reportToolUsageLog } from "../api/tool-usage.js";

reportToolUsageLog({
  ...buildToolUsageBase(props.tool),
  action: "convert",
  success: true,
  durationMs: 12,
  inputLength: input.value.length,
  outputLength: output.value.length,
});
```

## 11. 移动端适配

普通文本/文件工具基本不用额外处理，因为通用组件已经适配。

如果你写了定制组件，要检查：

| 你写了 | 手机端要做 |
| --- | --- |
| 多列 grid | `@media (max-width: 768px)` 下改成单列 |
| 横向 flex | 允许换行或改纵向 |
| 宽表格 | 外层加 `overflow-x: auto` |
| 固定大宽度 | 改成 `width: 100%` 或 `max-width: 100%` |
| 很长文本 | 加 `overflow-wrap: anywhere` 或滚动容器 |

原则：

- PC 样式不要乱动。
- 移动端覆盖写在 `@media (max-width: 768px)` 里。
- 不要让页面出现横向撑破。

## 12. 新增分类怎么做

如果要新增一个大类：

1. 改 `backend/app/configs/categories.json`
2. 改 `frontend/src/data/ui-mapping.js`
3. 如需调整首页展示，再看 `frontend/src/pages/Home.vue`

分类 slug 要稳定，例如：

```json
{
  "slug": "network",
  "name": "网络工具",
  "description": "网络检测和调试工具。",
  "enabled": true,
  "sort_order": 50
}
```

## 14. 常见坑

### tools.json 写错 JSON

表现：

- 后端启动失败。
- 分类页工具消失。

处理：

```bash
python -m json.tool backend/app/configs/tools.json >/dev/null
```

### module 和文件名不一致

表现：

- 工具卡片能看到。
- 点进工具执行时报模块加载失败。

检查：

```text
module = backend/app/tools/<module>.py 的文件名
```

### 后端模块没有 run()

表现：

- 工具执行失败。

处理：

确认工具模块里有：

```python
def run(...):
    ...
```

### 文件工具忘记补上传校验

表现：

- 上传阶段直接失败。

处理：

检查：

```text
backend/app/utils/validators.py
```

### component 写错

表现：

- 工具详情页打不开或组件不显示。

检查：

```text
frontend/src/pages/ToolPage.vue
frontend/src/data/ui-mapping.js
```

### 原生 select 混进页面

项目已经统一自定义下拉。

新增下拉优先使用：

```text
GlassSelect.vue
```

### 记录了用户完整输入输出

工具使用日志不要保存用户原始数据。

只能保存：

- 输入长度
- 输出长度
- 错误摘要
- 行为类型
- 成功失败

## 15. 自检清单

新增工具后逐项检查：

- `tools.json` 是合法 JSON。
- `slug` 没有重复。
- `module` 和文件名一致。
- 后端模块有文件说明注释。
- 后端模块有 `run()`。
- 文件工具做了上传类型/大小校验。
- 参数默认值合理。
- 错误提示是中文。
- 首页或分类页能看到工具卡片。
- 工具详情页能打开。
- 执行成功能看到结果。
- 执行失败不会页面崩溃。
- 结果区有复制、下载或清空能力时，尽量复用 `ResultPanel`。
- 纯前端工具不上传用户输入。
- 定制组件移动端不横向撑破。
- 需要后台统计时，工具使用日志只记录摘要。

## 16. 推荐开发顺序

最稳的顺序：

1. 先写最小可用逻辑。
2. 注册 `tools.json`。
3. 重启后端。
4. 打开页面确认工具能显示。
5. 测成功路径。
6. 测空输入、错误输入、异常文件。
7. 再补 UI 细节。
8. 最后补文档和注释。

不要一上来同时大改后端、前端、样式和配置。先跑通，再打磨。
