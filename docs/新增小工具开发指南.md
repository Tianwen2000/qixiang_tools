# 新增小工具开发指南

这份文档只讲当前仓库真实可用的接入方式，不讲抽象方案。

## 1. 先判断你要加的是哪种工具

新增工具前，先判断它属于哪类：

### A. 通用文本工具

适合：

- 输入一段文本
- 配几个简单参数
- 返回文本或下载文件

典型例子：

- JSON 格式化
- 正则替换
- 文本提取邮箱

### B. 通用文件工具

适合：

- 上传一个文件
- 配几个简单参数
- 返回文本或文件

典型例子：

- 图片压缩
- 图片转 Base64
- PDF 转 TXT

### C. 本地工具

适合：

- 不需要后端
- 浏览器自己就能完成逻辑

典型例子：

- 键盘测试
- 浏览器信息
- 响应式布局检测

### D. 定制工具

适合：

- 交互复杂
- 结果区不是普通文本/文件
- 需要特殊布局

典型例子：

- HTTP 测试
- WebSocket 测试
- 白板
- 图表工作台

## 2. 命名约定

### Python 工具模块

- 文件名：`snake_case`
- 配置里的 `module` 要和文件名一致

示例：

- 文件：`backend/app/tools/my_text_tool.py`
- 配置：`"module": "my_text_tool"`

### 工具 slug

- 用小写中划线

示例：

- `my-text-tool`

### Vue 自定义组件

- 用 `ToolXxx.vue`

示例：

- `ToolMyLocal.vue`

## 3. 新增一个文本工具

### 第一步：写后端模块

路径：

`backend/app/tools/<module_name>.py`

最小示例：

```python
from app.core.exceptions import AppException


def run(text: str, prefix: str = "", **_: dict) -> str:
    if not text.strip():
        raise AppException(message="请输入内容", code=4001, status_code=400)
    return f"{prefix}{text}"
```

### 第二步：注册到 `tools.json`

路径：

`backend/app/configs/tools.json`

最小示例：

```json
{
  "slug": "my-text-tool",
  "module": "my_text_tool",
  "name": "我的文本工具",
  "category": "text",
  "summary": "一句话摘要",
  "description": "工具的详细说明",
  "input_mode": "text",
  "result_type": "text",
  "component": "ToolTextForm",
  "enabled": true,
  "params": [
    {
      "key": "prefix",
      "label": "前缀",
      "type": "text",
      "default": "",
      "placeholder": "请输入前缀"
    }
  ]
}
```

### 第三步：重启后端

新增工具后，需要重启后端，让：

- `tool_loader.py`
- `tool_registry.py`

重新读取配置并导入模块。

## 4. 新增一个文件工具

### 第一步：写后端模块

典型签名：

```python
def run(input_path: str, output_dir: str, filename: str = "", content_type: str = "", **params) -> str:
    ...
```

说明：

- `input_path`：上传后的临时文件
- `output_dir`：本次请求的输出目录
- `filename`：原始文件名
- `content_type`：上传文件的 MIME 类型

### 第二步：注册 `tools.json`

文件工具通常会写成：

- `input_mode = "file"`
- `component = "ToolFileForm"`

### 第三步：补上传校验

路径：

`backend/app/utils/validators.py`

如果不补白名单，文件上传阶段就会直接被拦掉。

## 5. 新增一个本地工具

### 第一步：写 Vue 组件

路径：

`frontend/src/components/ToolMyLocal.vue`

### 第二步：在 `ToolPage.vue` 注册

- 引入组件
- 加进 `componentMap`

### 第三步：在 `tools.json` 注册

关键字段：

- `input_mode = "local"`
- `component = "ToolMyLocal"`

## 6. 参数类型怎么写

当前通用表单已支持：

- `text`
- `textarea`
- `select`
- `radio`

由这些组件负责渲染：

- `ToolTextForm.vue`
- `ToolFileForm.vue`
- `GlassSelect.vue`

### `select` 示例

```json
{
  "key": "mode",
  "label": "模式",
  "type": "select",
  "default": "fast",
  "options": [
    { "label": "快速", "value": "fast" },
    { "label": "精准", "value": "accurate" }
  ]
}
```

### 条件显示 `showWhen`

```json
{
  "key": "iv",
  "label": "IV",
  "type": "text",
  "showWhen": {
    "mode": "decrypt"
  }
}
```

## 7. 什么时候要改前端，什么时候不用改

### 不用改前端页面结构的情况

如果你新增的是普通文本工具或普通文件工具，通常只要：

1. 写后端模块
2. 加工具配置

前端就能自己渲染出来。

### 需要改单独组件的情况

如果出现下面任一情况，建议写独立组件：

- 需要画布
- 需要持续键盘/鼠标监听
- 需要多个结果面板联动
- 表单结构和普通工具明显不同

### 移动端适配：用通用组件几乎不用管，定制组件才需要

- **普通文本 / 文件工具（复用 `ToolTextForm` / `ToolFileForm`）**：手机端开箱即用，无需改动。全站通用样式已适配——参数区 `.param-row` 手机端单列、`.tool-form` / `.result-panel` 有窄屏内边距、输入控件占满宽、长文本自动换行；顶部分类导航在手机端单行横滑，`box-sizing`、防横向滚动都是全站共用的。
- **只有写定制 `ToolXxx.vue` 且自带布局时**，才需要顺手照顾手机端，重点四条（都写在 `@media (max-width: 768px)` 里）：

| 你写了… | 手机端要做的 |
| --- | --- |
| 多列 `grid` / 横向 `flex` | 塌成 `grid-template-columns: 1fr` 或改纵向 |
| 宽表格 | 外层包一个 `overflow-x: auto` 容器，别撑破页面 |
| 写死的 `width` / `min-width` 大值 | 改成 `100%` 或 `minmax(0, 1fr)` |
| 一排多个按钮 | `flex-wrap` + 缩小 `min-width` |

最省心的做法：定制组件尽量复用现成类名（`.tool-form` / `.param-row` / `.tool-actions` / `.result-panel`），白嫖已有的移动端适配，基本不用自己写媒体查询。

**铁律**：移动端样式只写在 `max-width` 媒体查询里，绝不改动 PC 端（≥1024px）的样式。

> 全站已采用的移动端策略，以及「Android 键盘弹出导致卡片重叠/渲染异常」的根因与解法（关 `backdrop-filter`、`interactive-widget`、`100dvh`），见《前后端架构与联动原理》8.5。

## 8. 新增一个分类怎么做

如果后面你要新开一个大分类，需要改：

1. `backend/app/configs/categories.json`
2. `frontend/src/data/ui-mapping.js`

必要时再看：

- `frontend/src/pages/Home.vue`

主要是首页展示顺序和分类主题色。

## 9. 最少改哪些文件

### 文本工具

1. `backend/app/tools/<module>.py`
2. `backend/app/configs/tools.json`

### 文件工具

1. `backend/app/tools/<module>.py`
2. `backend/app/configs/tools.json`
3. `backend/app/utils/validators.py`

### 本地工具

1. `frontend/src/components/<Component>.vue`
2. `frontend/src/pages/ToolPage.vue`
3. `backend/app/configs/tools.json`

## 10. 常见坑

### 1. `module` 和文件名不一致

后端会直接动态导入，名字对不上就加载失败。

### 2. 模块里没有 `run()`

`tool_registry.py` 会直接报错。

### 3. 文件工具忘了补 `validators.py`

会出现页面选了文件，但上传马上失败。

### 4. `component` 写了一个前端不存在的组件

工具详情页会回退失败或打不开，需要检查：

- `ToolPage.vue`
- `ui-mapping.js`

### 5. 新增参数没做后端校验

前端只是方便用户输入，真正的参数兜底还是要在后端模块里做。

## 11. 调试建议

### 后端调试

- 先看 `/docs`
- 直接调 `/execute` 或 `/upload`
- 失败优先看 `AppException` 中文提示

### 前端调试

- 看工具详情页有没有拿到正确的 `component`
- 看参数区有没有按 `params` 正常渲染
- 看结果区有没有正确识别 `text / file`

## 12. 新增工具后的自检清单

- `tools.json` 可正常解析
- 模块文件名和 `module` 一致
- 模块里有 `run()`
- `slug` 没和现有工具冲突
- 文件工具补了上传校验
- 首页能看到工具卡片
- 工具详情页可打开
- 执行成功后能得到结果
- 失败时返回中文错误
- 定制组件已照顾手机端（多列在 `≤768px` 塌单列、无横向溢出、按钮可点区足够）
- 必要时补 `backend/tests/test_api.py`

## 13. 当前最推荐的开发顺序

1. 先写后端逻辑
2. 再补 `tools.json`
3. 用 `/docs` 或接口直调验证
4. 最后进前端页面确认交互

这样最快，也最不容易绕远路。
