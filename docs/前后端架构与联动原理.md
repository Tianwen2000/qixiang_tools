# 前后端架构与联动原理

## 1. 项目定位

`琦湘工具集合` 是一个：

- 无数据库
- 前后端分离
- 配置驱动
- 一工具一模块
- 适合持续加小工具

的工具站工程。

它不是后台管理平台，也不是带用户体系的 SaaS。  
当前最核心的目标，是让“新增工具”变成一件稳定、低改动、容易复制的事。

```text
浏览器
  ├── 首页 / 收藏页 / 预览页 / 反馈页 / 打赏页

  └── 文本输入 / 文件上传 / 本地交互

          ▼

  ├── pages/*.vue
  ├── components/*.vue
  ├── api/*.js

          ▼
```

## 3. 后端是怎么组织的

### 3.1 关键目录

```text
backend/app/
├── main.py
├── api/routes/
├── core/
├── schemas/
├── services/
├── tools/
├── utils/
├── configs/
├── data/
└── temp/
```

### 3.2 每层职责

- `main.py`
  - 创建 FastAPI 应用
  - 注册日志、异常处理、CORS、路由、启动清理逻辑

- `api/routes`
  - `meta.py`：分类、工具列表、工具详情
  - `tools.py`：工具执行、文件上传、文件结果返回
  - `time.py`：北京时间与农历
  - `health.py`：健康检查

- `services/tool_loader.py`
  - 实时读取 `categories.json` 和 `tools.json`
  - 做工具筛选和详情查询

- `services/tool_registry.py`
  - 根据 `slug -> module`
  - 动态导入 `app.tools.<module>`
  - 强约束每个工具必须导出 `run()`

- `tools/*.py`
  - 真正的业务逻辑都在这里
  - 一工具一个 Python 模块

- `utils/validators.py`
  - 文件上传类型校验
  - 不同 `slug` 的白名单控制

- `temp/`
  - 文件类工具请求级输入输出目录
  - 请求结束自动清理

## 4. 前端是怎么组织的

### 4.1 关键目录

```text
frontend/src/
├── App.vue

├── pages/
├── components/
├── api/
├── data/
```

### 4.2 每层职责

- `App.vue`
  - 全局壳层
  - 注入 `SiteWallpaper`
  - 注入 `ToastViewport`
  - 承载路由页面，不额外制造页面刷新式过渡

- `router/index.js`
  - 维护首页、工具页、收藏页、预览页、反馈页、打赏页

- `pages/Home.vue`
  - 分类导航
  - 搜索
  - 工具网格
  - 首页缓存恢复

- `pages/ToolPage.vue`
  - 拉取工具详情
  - 决定渲染哪个工具组件
  - 展示工具头部和时间卡片
  - 保留返回上一分类/搜索结果的上下文

- `components/ToolTextForm.vue`
  - 通用文本工具
  - 渲染参数区
  - 调用 `/execute`
  - 管理结果区与清空输出

- `components/ToolFileForm.vue`
  - 通用文件工具
  - 渲染参数区
  - 调用 `/upload`
  - 管理文件结果与下载

- `components/GlassSelect.vue`
  - 全站统一下拉
  - 用来替代原生 `select`

- `components/ResultPanel.vue`
  - 统一结果展示
  - 支持复制、下载、清空输出

- `components/SiteHeader.vue`
  - 顶部导航
  - 品牌 logo
  - 分类切换
  - 收藏/预览/搜索入口

## 5. 配置驱动是怎么工作的

当前工具元信息完全来自两个 JSON：

- `backend/app/configs/categories.json`
- `backend/app/configs/tools.json`

### 5.1 分类配置负责什么

分类配置负责：

- 分类 `slug`
- 分类名称
- 分类说明
- 排序
- 是否启用

### 5.2 工具配置负责什么

工具配置负责：

- `slug`
- `module`
- `name`
- `category`
- `summary`
- `description`
- `input_mode`
- `result_type`
- `component`
- `enabled`
- `params`

也就是说：

- 后端靠它找到工具模块
- 前端靠它决定展示什么标题、什么参数、什么组件

## 6. 工具链路怎么串起来

### 6.1 工具列表链路

```text
Home.vue
  -> src/api/tools.js
  -> src/api/client.js
  -> GET /api/categories
  -> GET /api/tools
  -> tool_loader.py
  -> categories.json / tools.json
```

### 6.2 工具详情链路

```text
ToolPage.vue
  -> getTool(slug)
  -> GET /api/tools/{slug}
  -> tool_loader.get_tool_detail()
  -> tools.json
```

### 6.3 文本工具执行链路

```text
ToolTextForm.vue
  -> executeTextTool(slug, { text, params })
  -> POST /api/tools/{slug}/execute
  -> routes/tools.py execute_tool()
  -> get_tool_detail(slug)
  -> get_tool_module(slug)
  -> app.tools.<module>.run(text=..., **params)
```

### 6.4 文件工具执行链路

```text
ToolFileForm.vue
  -> uploadFileTool(slug, file, params)
  -> POST /api/tools/{slug}/upload
  -> validators.py 校验上传类型
  -> save_upload_file()
  -> app.tools.<module>.run(input_path=..., output_dir=..., filename=..., content_type=..., **params)
  -> FileResponse 或文本结果
  -> 清理临时目录
```

### 6.5 本地工具链路

部分工具不依赖后端，例如：

- 键盘测试
- 浏览器信息
- 响应式布局检测
- adb / Linux / Git / Docker 命令大全
- 白板
- 部分时间工具
- 图表工作台中的纯前端交互

这类工具通过 `component` 指向特定 Vue 组件，不走 `/execute` 和 `/upload`。

## 7. 工具页是怎么决定渲染哪个组件的

工具页核心入口是：

- `frontend/src/pages/ToolPage.vue`

判断顺序是：

1. 获取工具详情
2. 看 `tool.component`
3. 走 `resolveToolComponent()`
4. 在 `componentMap` 中选择最终组件

### 默认策略

- `text` -> `ToolTextForm`
- `file` -> `ToolFileForm`
- `mixed` -> `ToolTextForm`
- `form` -> `ToolTextForm`
- `local` -> 独立本地组件

### 什么时候需要单独写组件

- 交互复杂
- 布局不适合通用表单
- 需要持续监听鼠标/键盘
- 需要画布、白板、图表或复杂实时联动

## 8. 当前视觉系统是怎么接进页面的

这个项目现在已经不是“普通工具页”，而是有一套统一视觉系统。

### 8.1 页面基础风格

- 透明卡片
- 统一边框
- 统一圆角
- 轻动效
- 统一输入框、按钮和结果面板

### 8.2 统一控件体系

- `GlassSelect.vue`
- `ResultPanel.vue`
- `ToastViewport.vue`
- 统一透明输入框和按钮

要求是：

- 新增页面不要再直接写浏览器原生蓝色下拉
- 新增工具优先复用已有控件

### 8.3 动态背景体系

全站背景由：

- `frontend/src/components/SiteWallpaper.vue`
- `frontend/src/components/SeasonalForestScene.vue`
- `frontend/src/data/wallpaper-scenes.js`
- `frontend/src/styles/wallpaper.css`

统一实现。

当前四季主题：

- 春分
- 夏至
- 秋分
- 冬至

背景层级统一为：

```text
Base
Reading Veil
Atmosphere
Seasonal Forest
Motion
Noise
Vignette
```

这意味着后续即使要换动态背景风格，也优先改这三处，而不是到处散改。

#### 背景媒介与设备分支：电脑视频 / 手机图片（2026 年 6 月新增）

为解决移动端卡顿（全屏 `filter: blur()` + 海量渐变 + 几十个无限动画在手机 GPU 上填充率不足），默认背景改为**按设备分流**，上面那套 CSS 动态层退为「兜底层」：

- **电脑端**：四季循环**视频**背景；
- **手机端**（视口宽度 ≤ 767px）：四季**静态图**背景（更清晰、省流量、不卡）。

仍在 `SiteWallpaper.vue` 统一实现，关键点：

- 用 `window.matchMedia("(max-width: 767px)")` 判定 `isMobile`，**首帧即判定**——手机端不创建 `<video>`、不下载视频流量；
- 三态互斥：`useVideo`（电脑）/ `useStaticImage`（手机）/ `useCssScene`（视频不可用时的 CSS 兜底）；视频层 / 静态图层插在 `Base` 之上、`Reading Veil` 之下，叠一层可读遮罩 `wallpaper-video-shade`；命中视频或图片时给根节点加 `has-media`，关掉 `Base`/`Reading Veil` 里昂贵的 `blur`/`mix-blend` 伪元素；
- 素材放 `frontend/public/wallpaper/`，**文件名固定** `{season}.mp4` + `{season}.jpg`（season = `spring`/`summer`/`autumn`/`winter`，`.jpg` 同时用作视频 poster），规格说明见同目录 `README.md`；
- **回退链**：视频缺失 / 解码失败 / iOS 低电量禁播 → 视频 `@error` 自动回退到上面的 CSS 动态背景，绝不白屏；
- `WallpaperPreviewPanel.vue`（`/preview` 页「手动预览」）可手动切季节并带缩略图，切换时各设备仍按自身媒介显示（电脑视频 / 手机图片），季节计算独立于面板（默认 `auto` 跟随节气）。

### 8.4 导航与品牌体系

- 顶部导航由 `SiteHeader.vue` 承担
- 顶部导航固定在视口顶部，页面滚动不把导航带走
- 顶部装饰动画由 `HeaderQXMarquee.vue` 承担
- 左上静态品牌 logo 与导航滑动 logo 分离
- favicon 独立配置在 `frontend/index.html`

### 8.5 移动端适配策略与已知坑（2026 年 6 月）

整体原则：**PC（≥1024px）样式保持不变，移动端只通过 `max-width` 媒体查询新增覆盖**。新增普通工具一般无需关心移动端（详见《新增小工具开发指南》的「移动端适配」一节）。当前全站已采用的移动端处理：

- **顶部分类导航**：手机端（`≤768px`）从换行铺多行改为单行横向滑动（`flex-wrap:nowrap; overflow-x:auto` + 隐藏滚动条 + `.site-nav-item{flex:0 0 auto}`）。
- **通用表单参数区** `.param-row`：手机端改单列。
- **玻璃卡片去模糊**：手机端关掉 `backdrop-filter` 改实色背景（`.site-header` / `.tool-card` / `.tool-form` / `.result-panel` / `.detail-actions-card` 等）。
- **viewport**：`index.html` 声明 `interactive-widget=resizes-content` + `viewport-fit=cover`（桌面浏览器忽略，不影响 PC）。
- **高度单位**：移动端容器 `min-height` 用 `100dvh`（随键盘/地址栏动态收缩），老浏览器自动回退 `100vh`。

**已知坑（重要）**：Android（如华为 WebView）上**输入法/键盘弹出**会让 layout viewport 突然缩小，连锁触发 `position:fixed` 的 `.site-header` / `.site-wallpaper` 重定位 + `100vh` 高度突变 + 大量 `backdrop-filter` 玻璃卡片重新采样，导致**卡片错位、重叠、渲染残影**。解法就是上面的「移动端关 `backdrop-filter` 改实色 + `interactive-widget` + `100dvh`」组合（已验证有效）。若个别旧内核仍有残留，可把 `interactive-widget` 进一步改为 `overlays-content`（键盘浮层、页面完全不重排）。

涉及文件：`frontend/index.html`、`frontend/src/styles/global.css`、`frontend/src/styles/tool.css`。

## 9. 当前有哪些本地状态

虽然项目无数据库，但并不是完全无状态。

### 前端本地状态

- 首页缓存：`page-cache.js`
- 工具详情缓存：`page-cache.js`
- 收藏列表：`favorite-tools.js`
- 背景预览模式：`wallpaper-preview.js`
- 反馈暂存：反馈页 localStorage 降级

### 后端临时状态

- 文件工具请求级 input/output 目录
- 输出文件生命周期跟请求绑定

### 当前明确不做的事

- 用户系统
- 服务端历史记录
- 跨设备同步
- 后台内容管理系统

## 10. 当前最重要的维护原则

1. 不用数据库，不往主链路里硬塞数据库表
2. 工具元信息继续走配置驱动
3. 一工具一模块，不要把几十个工具揉到一个文件里
4. 简单工具优先复用通用组件
5. 前端控件继续走统一风格，不要回退成原生默认样式
6. 动态背景是辅助层，不能压过正文和工具交互

1. `backend/app/tools/<module>.py`

### 新增本地工具

1. `backend/app/configs/categories.json`

## 12. 当前边界和风险

- 文档转换链路走的是轻量转换，不承诺复杂排版百分百还原
- 图片抠图、OCR、复杂格式转换这类工具对输入质量比较敏感
- 键盘测试等高交互页面如果要逐像素对齐参考图，仍然可能继续微调
- 后续如果做桌面打包，需要重点关注 OCR、办公文档和加密依赖的打包问题
