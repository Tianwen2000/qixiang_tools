# 反馈遗留事项整理

> 更新：项目引入数据库后，反馈已改为**主后端 MySQL 落库** + **独立后台管理系统只读查看**，下面的 serverless/Worker 设想（#1、#2）已被取代并完成。本文保留作演进记录，最新现状见 [反馈系统整理](./README.md) 与 [AI 助手与登录系统说明](../AI助手与登录系统说明.md)。

## 已完成

- 独立反馈页 UI 已完成
- 反馈提交参数结构已明确
- 未配置远端接口时可本地暂存
- 打赏页已独立出来
- 反馈已落库主后端 MySQL（`feedback` 表，匿名可提交、登录记账号）
- 独立后台只读查看页已上线（看反馈 + 账号活动日志）

## 当前遗留项

### 1. 远端反馈写入服务未正式接入

状态：`已完成（改为主后端 MySQL 落库，不再依赖 Worker/表格）`

当前前端已经支持 `VITE_FEEDBACK_ENDPOINT`，但是否真正接到：

- Cloudflare Workers
- Google Sheets
- Airtable
- 飞书多维表格

仍取决于后续部署配置。

### 2. 反馈查看后台未单独建设

状态：`已完成（独立后台管理系统只读查看页）`

当前查看入口已迁移到自建独立后台，不再依赖第三方表格本身。

后续可以在该后台继续扩展访客、管理员账号和其它运营管理能力。

### 3. 通知能力未落地

状态：`待处理`  
优先级：`中`

可选目标：

- QQ 邮箱
- 钉钉机器人
- 飞书机器人

建议等落表稳定后再补。

### 4. 风控与反刷仍是建议态

状态：`待处理`  
优先级：`中`

当前尚未正式接入：

- Turnstile
- 更细的限流
- 反刷策略

### 5. 反馈字段标准还没有在 Worker 侧固化

状态：`待处理`  
优先级：`中`

前端字段结构已经基本确定，但 Worker 落表时仍需要把字段名、状态值、默认值彻底固定下来，避免后续表结构漂移。

## 建议推进顺序

1. 先接 Worker 落表
2. 再补通知
3. 最后补限流和风控

## 建议的落地成果

后续这条线如果彻底接完，至少应该产出：

1. 一个稳定可用的 `POST /feedback/submit`
2. 一份稳定字段定义
3. 一个表格查看入口
4. 一种通知方式
5. 一套轻量反刷配置
