# 项目代码文件总体说明

> 本文说明项目源码和常用配置文件的职责。`node_modules`、`dist`、`.venv`、`__pycache__`、临时上传目录、数据库文件和系统缓存属于生成文件，不作为源码说明重点。


```text

├─ main.py                   FastAPI 应用入口，注册中间件、路由和启动清理任务。
├─ api/routes/               HTTP 路由层，只处理请求、响应和调用服务。

├─ core/                     通用配置、异常、日志、响应格式。
├─ data/                     成语、歇后语等静态数据。
├─ db/                       SQLAlchemy 数据库连接、模型和建表逻辑。

├─ services/                 业务服务层，如登录、反馈、后台、工具加载。

└─ temp/                     上传和输出临时目录，运行时生成，不提交。
```

## 后端 tools 目录规则

`backend/app/tools/` 里的文件基本都是独立小工具模块，和 `backend/app/configs/tools.json` 的 `module` 字段一一对应。新增工具时通常需要：

```text
1. 在 backend/app/tools/ 新增 xxx.py。
2. 在 xxx.py 里实现 TOOL_META、run 或 upload 处理函数。
3. 在 backend/app/configs/tools.json 注册 slug、module、name、category、component、params。
4. 如需固定展示顺序，在 backend/app/services/tool_loader.py 的 CATEGORY_TOOL_ORDER 里配置。
```

常见工具模块分工示例：

```text
*_command_search.py            命令速查工具，前端用命令数据展示。
*_converter.py                 文件、文本、音视频、图片格式互转工具。
image_*.py                     图片处理工具，如压缩、裁剪、水印、取色。
text_*.py                      文本处理工具，如去重、排序、清理、统计。
today_*.py、market_quote.py    行情、价格和市场查询类工具。
game_*.py、*_game.py           纯前端小游戏的后端元信息占位。
abstract_ac.py、abstract_fan.py 赛博抽象小空调、小风扇元信息。
```

## 维护建议

- 业务逻辑优先写在后端 `services/` 或工具模块里，路由层保持薄。
- 新增普通工具优先复用 `ToolTextForm` 或 `ToolFileForm`，只有复杂交互再写专用组件。
- 真实 `.env.local`、数据库密码、临时文件和构建缓存不要提交；提交 example 和说明文档即可。
- 工具展示文字优先改 `backend/app/configs/tools.json`，前端刷新即可拿到新文案。
