# 本地开发登录后失效问题笔记

## 问题现象

项目是 FastAPI 后端 + Vue 前端。

本地开发时出现登录异常：

- 后台管理输入正确账号密码后，仍提示“请先登录后台”
- AI 聊天登录输入正确账号密码后，不显示登录信息
- 表现为登录成功后马上又变成未登录状态

## 根因

前端 `.env.local` 中配置了后端直连地址：

```env
VITE_API_BASE_URL=http://127.0.0.1:8000/api
```

导致浏览器请求接口时直接访问：

```txt
http://127.0.0.1:8000/api/xxx
```

但前端页面实际运行在：

```txt
http://localhost:5173
```

`localhost` 和 `127.0.0.1` 对浏览器 Cookie 来说不是同一个域。

项目登录态依赖 Cookie，所以接口跨域直连后，Cookie 无法稳定保存或携带，最终导致：

```txt
登录接口成功
↓
后续 /auth/me、/backoffice/me、/chat 读取不到 Cookie
↓
页面判断为未登录
```

## 正确做法

本地开发时，前端接口统一走 Vite 同域代理。

修改 `frontend/.env`：

```env
VITE_API_BASE_URL=/api
```

或者删除 `VITE_API_BASE_URL`，让前端默认走 `/api`。

同时确保 `vite.config.js` 中存在代理配置：

```js
proxy: {
  "/api": {
    target: "http://127.0.0.1:8000",
    changeOrigin: true,
  },
}
```

这样浏览器实际请求的是：

```txt
http://localhost:5173/api/xxx
```

再由 Vite 内部转发到：

```txt
http://127.0.0.1:8000/api/xxx
```

浏览器看到的是同域请求，Cookie 登录态就能正常生效。

## 修复步骤

1. 修改 `frontend/.env`

```env
VITE_API_BASE_URL=/api
```

2. 同步修改 `frontend/.env.example`

```env
VITE_API_BASE_URL=/api
```

3. 如果 AI 助手模块里有兜底地址，也改成 `/api`

```js
return envBase || "/api";
```

4. 重启前端

```bash
cd frontend
npm run dev
```

5. 清理浏览器旧 Cookie

建议清理：

```txt
localhost:5173
127.0.0.1:8000
```

6. 重新登录测试。

## 正确的 Network 表现

修复后，浏览器如果访问的是地址是 `localhost:5173`，则 F12 Network 里应该看到：

```txt
http://localhost:5173/api/auth/me
http://localhost:5173/api/backoffice/login
http://localhost:5173/api/backoffice/me
http://localhost:5173/api/chat
```

不应该再看到：

```txt
http://127.0.0.1:8000/api/auth/me
```

## 补充说明

直接在浏览器地址栏访问：

```txt
http://localhost:5173/api/backoffice/login
```

返回：

```txt
Method Not Allowed
```

这是正常的。

因为浏览器地址栏默认是 GET 请求，而后端登录接口是 POST：

```python
@router.post("/backoffice/login")
```

所以这个报错不代表登录接口坏了。

## 总结

这次问题不是账号密码错误，也不是 Cookie 登录方案有问题。

真正原因是：

```txt
前端 .env 把 API 地址写成了 http://127.0.0.1:8000/api
导致浏览器绕过 Vite 代理，直接跨域访问后端。
Cookie 登录态无法稳定携带，所以登录后马上失效。
```

一句话记忆：

```txt
本地 Cookie 登录时，前端接口尽量走 /api 同域代理，不要让浏览器直接请求 127.0.0.1:8000。
```
