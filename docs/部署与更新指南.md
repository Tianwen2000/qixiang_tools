# 部署与更新指南

> 记录生产服务器的部署架构，以及每次改完代码后如何更新上线。配合 [项目常用命令汇总](./项目常用命令汇总.md) 使用。

## 1. 部署架构

| 项 | 说明 |
|---|---|
| 服务器 | Ubuntu，项目目录 `/home/ubuntu/qixiang_tools` |
| 代码仓库 | GitHub `git@github.com:Tianwen2000/qixiang_tools.git`，`main` 分支 |
| 前端 | nginx **静态托管** `frontend/dist`（站点配置 `/etc/nginx/sites-enabled/qixiang_tools`，`root /home/ubuntu/qixiang_tools/frontend/dist`） |
| 接口反代 | nginx 把 `/api` 反代到 `http://127.0.0.1:8000/api/` |
| 后端 | systemd 服务 `qixiang-backend.service`（`uvicorn app.main:app`，端口 8000） |
| 后端运行环境 | 服务器专用虚拟环境 `backend/.server-venv`（**不是**本地的 `.venv`） |

**关键约定**：`frontend/dist` 是**纳入 git 的**，服务器不在本地打包——所以**改了前端必须先 `npm run build`，再把 `dist` 一起提交**，否则服务器拉下来的还是旧前端。

## 2. 日常更新流程

### 第一步：本地（Mac）打包并推送

```bash
cd /Users/a123/PycharmProjects/qixiang_tools/frontend
npm run build                       # 改了前端就要重新打包，刷新 dist

cd /Users/a123/PycharmProjects/qixiang_tools
git add -A
git commit -m "更新：xxx"
git push
```

### 第二步：服务器拉取（一行搞定）

```bash
cd /home/ubuntu/qixiang_tools && git pull && sudo systemctl restart qixiang-backend && systemctl is-active qixiang-backend
```

然后浏览器 **硬刷新**（Ctrl/Cmd+Shift+R）。nginx 不用 reload，它直接读 `dist` 里 git pull 下来的新文件。

## 3. 按改动类型，服务器要做什么

| 这次改了… | 服务器操作 |
|---|---|
| 只改前端（`frontend/`） | `git pull` + 浏览器硬刷新（**后端不用重启**） |
| 改了后端 `.py`（`backend/`） | `git pull` + `sudo systemctl restart qixiang-backend` |
| 改了 `backend/requirements.txt`（加依赖） | `git pull` → `./backend/.server-venv/bin/pip install -r backend/requirements.txt` → `sudo systemctl restart qixiang-backend` |
| 改了 nginx 配置 | `sudo nginx -t`（测试通过）→ `sudo systemctl reload nginx` |

> 拿不准就用「全量」一行：`cd /home/ubuntu/qixiang_tools && git pull && sudo systemctl restart qixiang-backend`，最多多重启一次后端，无副作用。

## 4. 验证

```bash
systemctl is-active qixiang-backend          # 应输出 active
curl -s 127.0.0.1:8000/api/health            # 应返回 {"code":0,...}
```

前端直接浏览器访问站点并硬刷新确认。

## 5. 回滚（上线后发现问题）

```bash
cd /home/ubuntu/qixiang_tools
git log --oneline -5                         # 找到要回退到的 commit
git reset --hard <上一个正常的 commit>         # 或：git revert <出问题的 commit>
sudo systemctl restart qixiang-backend
```

前端硬刷新。注意：`reset --hard` 会丢弃服务器上的本地改动——**服务器上不要直接改代码**，所有改动都从本地推。

## 6. 常见问题排查

- **前端没更新**：① 本地忘了 `npm run build` 或没把 `dist` 提交；② 浏览器缓存——硬刷新或用无痕窗口。
- **后端 500 / 起不来**：看日志
  ```bash
  sudo systemctl status qixiang-backend --no-pager
  sudo journalctl -u qixiang-backend -n 80 --no-pager
  ```
  常见原因：改了 `requirements.txt` 没 `pip install`，或代码报错。
- **接口 `/api` 报 502**：后端没起来 → 先 `systemctl is-active qixiang-backend`，再看日志。
- **nginx 改完没生效**：`sudo nginx -t` 通过后再 `sudo systemctl reload nginx`。

## 7. 关键路径速查

- 项目目录：`/home/ubuntu/qixiang_tools`
- 前端产物（nginx root）：`frontend/dist`
- 后端入口：`backend/app/main.py`（systemd `qixiang-backend`）
- 后端虚拟环境：`backend/.server-venv`
- nginx 站点配置：`/etc/nginx/sites-enabled/qixiang_tools`
- 后端日志：`sudo journalctl -u qixiang-backend`
