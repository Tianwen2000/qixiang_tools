然后：如果你改了数据库结构，比如新增字段、表结构变化，需要执行迁移命令。具体命令要看你项目用的是 Alembic、Django migration，还是自己建表。（本项目只有一个登录ai机器人涉及到sql，且用的是docker）；而且我在后端启动建表逻辑里加了兼容补列：加入一个反馈表的feedback.ip、feedback.device\_id、logs.device\_id这列是新增列，我只需要同步代码到服务器之后，后端服务重新启动就会执行 ensure\_schema() ，如果表已经存在但这些列不存在，会自动 ALTER TABLE ADD COLUMN 补上。

一般这几种情况才建议手动迁移数据库：

1改字段类型：比如 VARCHAR(64) 改成 TEXT、INT 改成 BIGINT，这类可能影响已有数据。

2删除字段或重命名字段：自动补列只能“加”，不能安全判断怎么删、怎么改名。

3字段要从可空改成不可空，并且没有默认值：旧数据可能不符合新约束，需要先清洗数据。

4新增索引、唯一约束、外键：尤其数据量大时，建索引可能锁表，最好手动安排时间窗口。

5新建表但有复杂初始化数据：如果只是空表，create\_all 可以自动建；如果要导入默认配置、权限、菜单等，就适合写迁移脚本。

6数据量变大以后：不是因为“大”本身必须迁移，而是大表执行 ALTER TABLE、加索引、改字段会更慢、更容易锁表，所以要手动控制。
