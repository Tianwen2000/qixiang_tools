## 6. 数据库结构变更

然后：如果你改了数据库结构，比如新增字段、表结构变化，需要执行迁移命令。具体命令要看你项目用的是 Alembic、Django migration，还是自己建表。（本项目只有一个登录 ai 机器人涉及到 sql，且用的是 docker）；而且我在后端启动建表逻辑里加了兼容补列：加入一个反馈表的 `feedback.ip`、`feedback.device_id`、`logs.device_id` 这列是新增列，我只需要同步代码到服务器之后，后端服务重新启动就会执行 `ensure_schema()`；如果表已经存在但这些列不存在，会自动 `ALTER TABLE ADD COLUMN` 补上。

一般这几种情况才建议手动迁移数据库：

1. 改字段类型：比如 `VARCHAR(64)` 改成 `TEXT`、`INT` 改成 `BIGINT`，这类可能影响已有数据。
2. 删除字段或重命名字段：自动补列只能“加”，不能安全判断怎么删、怎么改名。
3. 字段要从可空改成不可空，并且没有默认值：旧数据可能不符合约束，需要先清洗数据。
4. 新增索引、唯一约束、外键：尤其数据量大时，建索引可能锁表，最好手动安排时间窗口。
5. 新建表但有复杂初始化数据：如果只是空表，`create_all` 可以自动建；如果要导入默认配置、权限、菜单等，就适合写迁移脚本。
6. 数据量变大以后：不是因为“大”本身必须迁移，而是大表执行 `ALTER TABLE`、加索引、改字段会更慢、更容易锁表，所以要手动控制。

### HTTPS 仓库认证说明

- 公有仓库：执行 `git clone`、`git pull` 通常不需要账号或密码。
- 私有仓库：GitHub 会要求填写 GitHub 用户名；密码位置填写 Personal Access Token（PAT），不能填写 GitHub 登录密码。服务器只拉取代码时，Fine-grained PAT 给目标仓库 `Contents: Read-only` 权限即可。PAT 不要写进命令、文档或提交到 Git。

## 10. 环境文件与数据库同步

### `.env` 与 `.env.local`

`backend/app/core/config.py` 已支持 `env_file=(".env", ".env.local")`，按启动工作目录读取；当前 `qixiang-backend` 的工作目录是 `/home/ubuntu/qixiang_tools/backend`。

- 服务器使用 `backend/.env`，本地使用 `backend/.env.local`，分别维护，不提交到 Git。
- 同名配置优先级：进程环境变量 > `.env.local` > `.env` > 代码默认值。不要把本地 SQLite 的 `.env.local` 传到服务器覆盖 MySQL 配置。
- 更新配置读取代码或环境文件后，重启后端；只有修改 systemd 服务文件时才需要先执行 `sudo systemctl daemon-reload`。

```bash
sudo systemctl restart qixiang-backend
sudo systemctl status qixiang-backend --no-pager
# 登录仍提示服务不可用时，查看数据库连接错误
sudo journalctl -u qixiang-backend -n 50 --no-pager
```

### 数据库迁移与同步

Git/当前 rsync 命令只同步代码，不同步环境文件和数据库数据。本地 `backend/local_ai.db` 是 SQLite，线上 `qixiang_tools` 是 MySQL，两者数据独立。

- 日常更新代码：继续连接原来的线上数据库，无需搬迁数据；修改 `DATABASE_URL` 只改变连接目标，不会迁移数据。
- 表结构变化：补充更正第 6 节，`ensure_schema()` 在首次使用相关数据库功能时触发，自动建缺失表和补兼容清单中的列，不是重启后立即迁移；其他结构变化需另行处理。
- 更换服务器或确需复制数据时，才单独备份、迁移。
- SQLite → MySQL：需要专门导出、转换、导入，处理字段类型、主键和外键；不能直接复制 `.db` 或把 SQLite 导出的 SQL 原样导入 MySQL。

```bash
# 线上 MySQL 备份（交互输入密码；备份留在项目目录外）
mysqldump -h 127.0.0.1 -P 3306 -u qixiang -p --single-transaction --no-tablespaces qixiang_tools > ~/qixiang_tools_$(date +%Y%m%d_%H%M%S).sql

# 仅用于 MySQL → MySQL 迁移：替换占位项，目标应为已创建的空库
mysql -h 新服务器地址 -u 数据库用户 -p 新建空库名 < 备份文件.sql
```

迁移后核对表和记录数量，修改服务器 `.env` 的 `DATABASE_URL` 并重启后端，再验证登录和日志写入；不要用本地测试数据覆盖现有生产数据。

## 11. 线上数据库位置（Docker）

线上 MySQL 跑在 Docker 容器 `qixiang-mysql` 里，项目通过 `127.0.0.1:3306` 连接。数据库文件在容器内的 `/var/lib/mysql`，宿主机实际目录由 Docker 数据卷管理，不要直接改里面的文件。

```bash
# 查看容器和运行状态
sudo docker ps

# 查看宿主机目录 ↔ 容器目录的真实映射
sudo docker inspect qixiang-mysql \
  --format '{{range .Mounts}}{{println .Source "->" .Destination}}{{end}}'

# 进入数据库看表
sudo docker exec -it qixiang-mysql mysql -u qixiang -p qixiang_tools
```

进入 MySQL 后执行 `SHOW TABLES;`；备份、迁移也使用 MySQL 命令，不要复制 `/var/lib/docker/volumes` 下的数据库文件。

服务器里的`.server‑venv`只是 Python 虚拟环境，和 MySQL 数据库完全无关，项目通过网络连接 Docker 内的 MySQL 服务，不要到宿主机`/var/lib/mysql`去找数据库文件。
