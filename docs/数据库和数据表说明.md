# 数据库和数据表说明

本文档说明琦湘工具站当前后端使用的数据库、数据表和字段用途。

## 数据库来源

后端通过环境变量 `DATABASE_URL` 连接数据库。

常见配置示例：

```env
DATABASE_URL=mysql+pymysql://qixiang:mysqltianwen@127.0.0.1:3306/qixiang_tools?charset=utf8mb4
```

当前项目支持：

- MySQL：线上和正式本地开发推荐使用。
- SQLite：测试用例和临时调试可用。

数据库连接由 `backend/app/db/session.py` 统一管理，ORM 模型定义在 `backend/app/db/models.py`。

## 数据库名称

默认数据库名：

```text
qixiang_tools
```

如果 `.env.local` 里的 `DATABASE_URL` 指向其他库名，则实际库名以 `.env.local` 为准。

## 自动建表

项目使用 SQLAlchemy ORM。

调用登录、反馈、日志等数据库相关接口时，会触发 `ensure_schema()` 自动建表。

目前兼容补字段逻辑在 `backend/app/db/init_db.py`，用于给旧表补充新增字段，例如：

- `feedback.ip`
- `feedback.device_id`
- `logs.device_id`

注意：简单新增字段可以自动补；复杂结构调整、字段改名、大数据量迁移，仍建议单独写迁移脚本。

## 表总览

| 表名 | 用途 |
| --- | --- |
| `users` | 天问 AI 登录用户账号表 |
| `sessions` | 天问 AI 登录会话表 |
| `feedback` | 用户反馈表 |
| `logs` | 天问 AI 账号活动日志表 |
| `tool_usage_logs` | 用户工具使用行为日志表 |

## users

天问 AI 登录用户账号表。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT / INTEGER | 主键，自增 |
| `account` | VARCHAR(11) | 用户账号，唯一索引，通常是 11 位账号 |
| `password_hash` | VARCHAR(255) | 密码哈希，不存明文密码 |
| `created_at` | DATETIME | 注册时间，UTC 时间 |
| `last_login_at` | DATETIME | 最近登录时间，可为空 |

主要用途：

- 用户注册。
- 用户登录校验。
- 后端根据会话反查账号。

## sessions

天问 AI 登录会话表。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT / INTEGER | 主键，自增 |
| `token` | VARCHAR(64) | 服务端会话令牌，唯一索引，写入 httpOnly Cookie |
| `user_id` | BIGINT / INTEGER | 关联 `users.id` |
| `account` | VARCHAR(11) | 冗余账号，便于快速读取 |
| `created_at` | DATETIME | 会话创建时间，UTC 时间 |
| `expires_at` | DATETIME | 会话过期时间，默认 30 天 |

主要用途：

- 保存用户登录态。
- 用户主动退出登录时删除对应会话。
- 后端通过 Cookie 中的 token 查询当前用户。

说明：

- 天问 AI 登录态是服务端会话，不是纯前端 localStorage。
- Cookie 过期和服务端 session 过期时间应保持一致。

## feedback

用户反馈表。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT / INTEGER | 主键，自增 |
| `feedback_type` | VARCHAR(32) | 反馈类型，例如问题反馈、功能建议、内容纠错 |
| `content` | TEXT | 反馈内容 |
| `tool_slug` | VARCHAR(128) | 工具 slug |
| `tool_name` | VARCHAR(128) | 工具名称 |
| `tool_url` | VARCHAR(512) | 工具 URL |
| `contact_type` | VARCHAR(32) | 联系方式类型 |
| `contact_value` | VARCHAR(256) | 联系方式内容 |
| `submitted_page` | VARCHAR(512) | 提交反馈时所在页面 |
| `user_agent` | VARCHAR(512) | 浏览器 UA |
| `ip` | VARCHAR(64) | 提交反馈时后端看到的 IPv4 |
| `device_id` | VARCHAR(128) | 前端生成的本地设备 ID |
| `account` | VARCHAR(11) | 已登录时记录账号，匿名反馈为空 |
| `created_at` | DATETIME | 创建时间，UTC 时间 |

主要用途：

- 后台“用户反馈”页面展示。
- 记录用户反馈来源页、工具、账号、IP、设备 ID 和 UA。

隐私说明：

- 反馈内容是用户主动填写的文本，会保存。
- IP、UA、设备 ID 用于排查问题和定位异常反馈来源。

## logs

天问 AI 账号活动日志表。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT / INTEGER | 主键，自增 |
| `event` | VARCHAR(16) | 事件类型：`register`、`login`、`logout` |
| `account` | VARCHAR(11) | 账号 |
| `device_id` | VARCHAR(128) | 前端设备 ID |
| `ip` | VARCHAR(64) | 后端看到的 IPv4 |
| `user_agent` | VARCHAR(512) | 浏览器 UA |
| `created_at` | DATETIME | 创建时间，UTC 时间 |

主要用途：

- 后台“天问 AI 账号活动日志”页面展示。
- 排查注册、登录、退出登录相关问题。

## tool_usage_logs

用户工具使用行为日志表。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT / INTEGER | 主键，自增 |
| `account` | VARCHAR(11) | 已登录账号；未登录为空 |
| `device_id` | VARCHAR(128) | 前端生成的本地设备 ID |
| `ip` | VARCHAR(64) | 后端看到的 IPv4 |
| `user_agent` | VARCHAR(512) | 浏览器 UA |
| `source_page` | VARCHAR(512) | 来源页面 |
| `tool_id` | VARCHAR(128) | 工具 slug |
| `tool_name` | VARCHAR(128) | 工具名称 |
| `category` | VARCHAR(64) | 工具分类 slug，例如 `ops`、`format` |
| `action` | VARCHAR(32) | 操作类型：`view`、`click`、`convert`、`copy`、`clear` |
| `success` | VARCHAR(8) | 执行结果：`success`、`fail`，或为空 |
| `duration_ms` | INTEGER | 耗时，单位毫秒 |
| `input_length` | INTEGER | 输入长度或上传文件大小 |
| `output_length` | INTEGER | 输出长度或结果文件大小 |
| `error_code` | VARCHAR(64) | 错误码 |
| `error_message` | VARCHAR(512) | 截断后的错误信息 |
| `created_at` | DATETIME | 创建时间，UTC 时间 |

主要用途：

- 后台“用户工具使用日志”页面展示。
- 统计用户使用了哪个工具、做了什么操作、是否成功、耗时多久。
- 排查工具异常，但不保存用户完整输入和完整输出。

隐私说明：

- 不保存用户完整输入内容。
- 不保存用户完整输出内容。
- 只保存输入输出长度、错误摘要和行为统计字段。

| slug | 中文 |

| `image` | 图片 |

| `time` | 时间 |
| `game` | 益智游戏 |

## 操作字段说明

`tool_usage_logs.action` 的常见值：

| 值 | 中文 |
| --- | --- |
| `view` | 查看工具 |
| `click` | 点击按钮 |
| `convert` | 执行转换 |

| `clear` | 清空内容 |

## 数据读取方式

后台管理页面不直接读项目文件夹，也不读 `log/` 日志文件。

后台页面通过接口读取数据库：

| 页面 | 接口 | 数据表 |
| --- | --- | --- |
| 用户反馈 | `GET /api/backoffice/feedback` | `feedback` |
| 天问 AI 账号活动日志 | `GET /api/backoffice/logs` | `logs` |
| 用户工具使用日志 | `GET /api/backoffice/tool-usage-logs` | `tool_usage_logs` |

## 项目 log 文件夹和数据库的区别

`log/` 文件夹保存的是程序运行日志，例如：

- DEBUG 调试日志
- INFO 普通信息日志
- WARN 警告日志
- ERROR 错误日志

这些文件用于开发和运维排查，不作为后台管理页面的数据来源。

后台管理页面展示的数据来自数据库表。

## 常用检查命令

进入 MySQL 容器：

```bash
docker exec -it qixiang-mysql mysql -u qixiang -p qixiang_tools
```

查看所有表：

```sql
SHOW TABLES;
```

查看表结构：

```sql
DESC users;
DESC sessions;
DESC feedback;
DESC logs;
DESC tool_usage_logs;
```

查看最近反馈：

```sql
SELECT id, feedback_type, account, ip, tool_name, created_at
FROM feedback
ORDER BY id DESC
LIMIT 20;
```

查看最近工具使用日志：

```sql
SELECT id, account, ip, tool_name, category, action, success, duration_ms, created_at
FROM tool_usage_logs
ORDER BY id DESC
LIMIT 20;
```

## 什么时候需要手动迁移

通常不需要手动迁移：

- 新环境首次启动。
- 新增简单表。
- 少量新增字段，并且 `init_db.py` 已写兼容补字段逻辑。

建议手动迁移：

- 字段改名。
- 字段类型变化。
- 删除字段。
- 拆表或合表。
- 已有数据量较大，需要分批迁移。
- 需要补历史数据。
- 需要创建复杂索引或调整索引。

上线前如果涉及手动迁移，建议先备份数据库。
